# Trophy Tide — Knights Tower Defense & Whale Boss

**Difficulty:** extreme  |  **Stack:** HTML/CSS/JS — one self-contained `.html` file, double-click `file://`, any framework/engine allowed only if bundled/inline  |  **Estimated time:** 8–14 hours

## The Problem

A 6-year-old in 1st year of schooling loves castles, knights, and winning a big trophy — but ordinary Tower Defense is unreadable for that age, and ordinary school exercises feel like being pulled out of the game. **Trophy Tide** must fuse the two: a single-player competitive battle (Tower Defense base + Capture-the-Flag feeling: defend your side, push toward the enemy's prize before the simulated rival wins) where learning IS the power-up. Units fight on their own with no micromanagement; the child watches, reacts, taps one big button to call an educational challenge (letters, counting, `2 + 3`), and a correct answer visibly turns the battle — shields hold, knights surge, the trophy gets closer. Without this loop (observe → react → educational challenge → boost → victory), either the game is a cartoon the child can't influence, or the maths is homework wearing a costume. You will build the full adventure — castle, mountain, cave, boats/lake, and a whale boss with three signature attacks — as one offline `.html` file a child can open by double-clicking.

## Requirements

1. **Single-file launch (offline).** The entire game ships as one `.html` file with all CSS/JS (and any framework/engine) inline/bundled. Double-clicking it (`file://` URL) in current Chrome or Firefox opens the game with zero console errors, zero build step, and zero required network requests. (FR-12 architecture base.)
2. **Start screen & single-player setup.** First screen shows the title, a 3-step picture/word how-to-play (Watch → Answer → Win the trophy), a big START button, and a level-select showing 5 levels (1 Castle, 2 Mountain, 3 Cave, 4 Boats/Lake, 5 Whale Boss) with levels 2–5 locked until the previous one is won. Starting level 1 spawns the player's base on one side, the simulated rival's base on the other, and a large trophy/goal marker between or beyond them. (FR-01, FR-09, FR-13.)
3. **Automatic battle simulation — no micromanagement.** Units (knights, then themed units) spawn automatically up to a visible field capacity (default: max 6 player units + 6 rival units on screen), advance along a lane/path toward the rival side, fight rival units or the rival base/boss on contact using internal stats, and the child NEVER selects, drags, or orders an individual unit — there is no unit-selection UI at all. A simulated rival AI spawns and pushes its own units with comparable rules so the battle visibly evolves without child input. (FR-02, FR-16.)
4. **Visible advantage & progress (no numbers for the child).** Internally a single tug `progress` meter 0–100 (0 = rival goal, 100 = player goal, 50 = start); at all times the screen shows: (a) a tug-of-war progress bar/flags row driven by that meter and drifting toward whoever is winning, (b) the two bases and the trophy with shrinking/growing distance cues spatially lerped from the same meter, and (c) simple face/icon signals (e.g. smiling vs worried knight) — never percentages or stat sheets. An adult tester can tell who is winning within 5 seconds of glancing at the screen. (FR-03.)
5. **Main loop observe → react → challenge → boost → victory.** Every level runs the loop: battle auto-evolves → an educational opportunity appears → the child answers → a boost visibly changes the battle within 2 seconds (units glow/speed up, shields appear, progress bar jumps) → the match ends when one side reaches the level goal, followed by a conquest animation + celebration + victory screen with the trophy. (FR-02, FR-06, FR-09, FR-10.)
6. **Educational challenges: 1st-year letters & maths (flashcard format).** The challenge card shows one big question, an optional picture/countable objects, and 3 large tappable answers (one correct). The bank must include at least: 8 letter-recognition items (e.g. "Which letter is B?", options B/D/P) and 8 maths items (counting to 10, additions with sums ≤ 10, subtractions with minuends ≤ 10 — see Sample Data). Text is minimal; every card is solvable by tapping/clicking one answer. (FR-04.)
7. **Dual activation: automatic + child-initiated (both observable).** Both triggers read the same single 0–100 meter from req. 4. (a) AUTOMATIC: the game pops a challenge card on its own at least when the player is losing ground (rival progress ≥ 65%, i.e. meter ≤ 35) and at least once when the player is close to winning (player progress ≥ 80%, i.e. meter ≥ 80). (b) CHILD-INITIATED: a permanent big "POWER!" button (≥96px, always visible during battle) opens a challenge card on demand, with a short cooldown (default 10 s, shown as a filling ring). Both paths grant the same boosts. (FR-05.)
8. **Correct answer → immediate visible boost (default mapping).** Each correct answer grants one boost, announced with a banner + sound/shape animation the child can name ("shields up!", "knights run fast!"). Default mapping (variation of values allowed, mapping itself required): maths-correct → Shield Wall (player units invulnerable 8 s, visible bubble); letter-correct → Swift Charge (player units +60% speed for 10 s, motion lines); any 3rd consecutive correct → Rally (instantly return one resting unit to the field + heal all player units to full). The wrong-answer path must never grant a boost. (FR-06.)
9. **Wrong answers are never punished.** A wrong tap shakes the card gently, plays a kind prompt ("Try again!"), highlights one wrong option as eliminated OR shows a counting hint, and lets the child retry the SAME question until correct or dismiss it (X button) with the battle continuing unchanged — no score loss, no unit death, no lockout. The same question reappears within the next 3 cards (spaced retry). (FR-07.)
10. **Dynamic difficulty that needs learning (fair, never a hard block).** The rival AI must create at least one comeback-needing moment per level: if the player leads by a large margin early, rival spawn rate rises up to +50%; if the player trails badly, the game offers (never forces) a bonus challenge via a glowing POWER! button. DEFAULT (variation allowed but must be stated on the victory screen's "grown-up note"): a challenge is always an opportunity — victory is NEVER hard-gated behind answering (the battle can always be won without answering, only slower). Balance default: base simulation slightly favors the rival via named constant `RIVAL_SPAWN_BIAS = 1.10` (rival spawns ~10% faster before boosts), so idling 60 s reliably loses yet a rare unattended lucky run can still win; each correct answer accelerates the player toward 100% so active play wins in reasonable time. Rubber-banding parameters and `RIVAL_SPAWN_BIAS` must be constants at the top of the script. (FR-08.)
11. **Five themed levels, same core mechanic.** Sequential campaign (default order; level-select choice after unlocking is an allowed variation): 1 Castle (knights vs rival knights, trophy), 2 Mountain (same rules, rocky lane + obstacles art, snow/rock palette), 3 Cave (enclosed art, knights' house/fort + swords/shields décor), 4 Boats/Lake (water lane, boat bases, swimming/wading units), 5 Whale Boss (see req. 13). Each level reuses the identical loop, progress bar, card UI, and boost set; only art, lane shape, rival stats (+10% HP per level, stated in a code comment), and the goal dressing change. Winning a level unlocks the next and shows its new setting intro card. (FR-13, FR-14.)
12. **Unit continuity across levels.** The player's knights keep the same names/colors/shield emblems in every level (visual identity persisted across the campaign in the same session), and any swords/shields earned (req. 14) stay visibly equipped. Whether they carry permanent stat bonuses is OPEN — default: purely visual continuity (no hidden stat carry), stated in a code comment; a persistent-stat variation is allowed if the victory screen's grown-up note says so. (FR-15.)
13. **Whale boss level with exactly the 3 signature attacks.** Level 5 replaces the rival base with a big WHALE boss (HP bar as hearts/icons, not numbers — hearts are flavor reflecting the same 0–100 meter from req. 4, e.g. `hearts = ceil((100 - progress) / 20)`) that stays on screen and uses all three attacks on a visible telegraph (splash warning ≥0.8 s before each): (a) WATER JETS — a jet sweeps the lane every ~12 s, knocking player units backward one step/stunning them 2 s; (b) PULL BY THE FEET — every ~20 s a unit is grabbed with a splash + "HELP!" bubble and dragged toward the whale for 3 s unless the child answers any challenge card correctly to free it instantly; (c) AUXILIARY CREATURES — at least 2 small fish/rays minions spawn periodically, slow (40% speed aura) or block one player unit each until bumped twice. Victory = pushing the same 0–100 meter to 100% (overtaking/neutralizing the whale's block; "slaying" art is allowed but must stay playful, no graphic violence). The boss is observably tougher: named constant `PAR_TIME_L1` (default 120 s reference for level 1, at top of script) applies, and level 5 takes ≥1.5× `PAR_TIME_L1`. (FR-20, FR-21.)
14. **Swords & shields as thematic rewards.** Winning levels 1 and 3 grants a visible SWORD and SHIELD respectively, shown on a reward card, added to a persistent trophy-shelf/collection screen, and visibly equipped on the knights from then on. DEFAULT (mark variation in code comment): cosmetic + a tiny stated bonus (shield = one free hit-block per unit per level; sword = +1 bump damage) — a pure-cosmetic variation is allowed. (FR-22.)
15. **Unit lifecycle: spawn → fight → temporary defeat → return.** Units enter from their base up to capacity, fight on contact (bump = damage exchange with hearts/flash feedback), and a defeated player unit NEVER vanishes permanently: it visibly walks/limps back to base (or fades with a "resting…" bubble) and re-enters after a fixed rest (default 8 s, shown as a snoozing icon at base). No permadeath, no unit shop, no resurrect cost. (FR-17, FR-18.)
16. **At least two distinguishable unit classes (minimal set).** The roster must implement ≥2 classes with visibly different sprites and stated constants: default STURDY (slow, survives 3 bumps, e.g. shield-knight) and SWIFT (fast, falls in 1 bump, e.g. squire with flag). The child does not pick or manage classes — the spawner alternates them automatically. Adding more classes later must require only a new entry in one `UNIT_TYPES` table (no loop rewrites). (FR-19.)
17. **Trophy victory + celebration + collection + choose-your-prize.** Every level win triggers within 1 s: a conquest animation (units gather at the trophy), confetti/cheer, a VICTORY screen naming the level, the trophy or thematic prize displayed big, then an observable choose-your-prize moment where the child picks 1 of 3 large tappable trophy presentations (e.g. big cup / shiny star / crown, each ≥64px) — the picked prize is shown big and added to a "Collection" shelf that persists for the session (and in `localStorage` if available) showing earned trophies/swords/shields plus the chosen presentation. Level 5's win additionally shows the big CUP. A post-choice "Play again / Next level" navigation preserves autonomy. (FR-10.)
18. **Deferred extras are stubbed, not built.** A "Square / Shop" button exists but honestly opens a "Coming soon" panel listing the future extras (juice, chocolate, sweets, clothes, costumes — see Sample Data) WITHOUT any purchasable or gameplay-affecting behavior; the core file must contain a single `FUTURE_REWARDS` array stub where they will plug in. Building a working shop now is out of scope. (FR-11.)
19. **Theme architecture = one engine, many skins.** All levels run on one shared battle/card/boost engine: art, lane waypoints, palettes, and rival tuning live in a single `LEVELS` config array (5 entries), and adding a 6th theme must be a data-only edit (no new engine code). A code comment must state exactly which lines to copy. (FR-12.)
20. **Match end & scoreboard.** The match ends the moment the single 0–100 meter from req. 4 hits either goal (0 = rival win, 100 = player win); the winner is whoever got there first (player OR rival — the rival CAN win, triggering a kind "Try again!" screen with instant replay). A persistent session scoreboard shows stars per level (1 star win / 2 stars win-with-≥3-correct / 3 stars win-with-no-wrong-answer) — observable after each match. (FR-09.)
21. **Child-proof input & pacing.** All interaction is tap/click on targets ≥64px (POWER! ≥96px), keyboard optional (Space = POWER!, 1/2/3 = answers, Enter = start/confirm). No reading required beyond single letters and digits 0–10; no timers that punish slow readers (cards never auto-expire; battle pauses softly — units slow to 25% — while a card is open, default; state it in a comment). Battle speed default ≤1 unit-bump per second so a 6-year-old can follow it. (Pedagogical integration.)
22. **Deterministic-optional seed & grown-up note.** A `?seed=` URL parameter (or a seed box on the start screen, either is fine) controls question order and rival timing for reproducibility; absence of a seed must still play fully. A discreet "grown-ups" line/panel lists ALL chosen defaults so a tester can verify each pending decision was resolved observably: continuous-sim, opportunity-not-gate (with `RIVAL_SPAWN_BIAS`), auto-return 8 s, cosmetic-vs-stat rewards, sequential levels, boost mapping, retry policy (hint + retry + resurface within 3 cards), whale-victory = push-to-100% (with `PAR_TIME_L1`), class minima (Sturdy/Swift), prize-choice (1 of 3 presentations). (§19 decisions preserved.)
23. **Sign-off:** the start screen must carry a visible footer line giving the date and time the solution was produced and the model/author that produced it (e.g. `built by <model> · 2026-10-30 12:00`), and the same credit must appear as an HTML comment on the first lines of the file.

## Constraints

- Exactly one `.html` file (named per Deliverable); all CSS/JS inline. Any framework or game engine (e.g. Phaser, PixiJS) is allowed ONLY if its code is bundled/inlined in the file — no `<script src>`/`<link>` that must load from disk or network to play.
- Must run from a `file://` double-click in current Chrome or Firefox with zero console errors; no build step, no modules loaded from disk, no external fonts/images required to play (system fonts + inline SVG/canvas art only).
- No network calls to play; no servers, no analytics. Optional remote assets/fonts are allowed only as progressive enhancement that silently degrades offline.
- Storage: none required; `localStorage` may be used ONLY for the trophy/collection shelf and last-unlocked level — never required to start or finish a level (private-mode must still play).
- Input: mouse/touch tap only is sufficient (targets ≥64px); keyboard shortcuts (Space/1-2-3/Enter) are a required alternative but pointer-only play must be fully possible. No text typing by the child except the optional seed box.
- Keep every tuning number (capacities, cooldowns, HP, speeds, rubber-band caps, boost durations) as named constants at the top of the script; no magic numbers buried in logic.
