About RepoDeck

single-file GitHub repository workbench · v1.0

What this is

RepoDeck turns a public GitHub URL into an interactive repository explorer. Browse directories on demand, read syntax-highlighted source, render Markdown, and execute standalone HTML pages in an isolated iframe. Everything lives in this one HTML file — no build, server, or account.

Quick start

  • Paste https://github.com/owner/repo, a /tree/branch/path URL, or a file URL into the home field.
  • Use the sidebar to move through folders. Breadcrumbs and the back/forward buttons keep your trail.
  • Open an .html file and choose Preview as App to resolve its local CSS, JS and images and run it sandboxed.
  • Press Ctrl/⌘+K for quick-open, or use / to jump to filename search.
  • Recent repositories and theme preferences are stored in your browser only.

Source, Markdown & preview

Source view displays the exact file with line numbers and highlighting, plus copy and download. Markdown opens rendered by default; the toggle switches to raw source and the choice is remembered across files. HTML opens as source until you explicitly choose Preview as App — viewing and executing are always separate actions.

How preview dependencies resolve

RepoDeck parses the HTML document, then resolves each local reference against the file's repository location (including ../, root-relative paths, spaces and URL encoding). Stylesheets, scripts and images are fetched from GitHub's raw endpoint and embedded into a reconstructed document:

  • CSS url(...) assets become data URLs and @import chains are inlined with cycle detection.
  • Classic scripts are inlined in original order; deferred and module scripts execute after parsing. Module imports are rewritten recursively.
  • External CDN references are left alone so the browser can load them normally.
  • Successful resources are cached for the session; failures are listed in the preview's dependency panel.

GitHub API limits & private repos

RepoDeck uses GitHub's public REST API without a token. Unauthenticated requests are limited to roughly 60 per hour per IP address; GitHub may also throttle shared networks. Directory listings, file contents and trees are cached per session to conserve requests. If you hit a limit, RepoDeck shows the reset time — wait, or try another network.

Private repositories, tokens and OAuth are intentionally not supported: a token cannot be embedded safely in a standalone file, and GitHub's API would reject unauthenticated access. Only public repositories work.

Security & honest limitations

Repository content is treated as untrusted. Markdown is sanitized with an allowlist, raw HTML is cleaned, source files never execute in this page, and previews run in an iframe with sandbox="allow-scripts" and no allow-same-origin. That gives previewed code an opaque origin: it cannot read this page's DOM, JavaScript variables, localStorage, or history.

Sandboxing is not a guarantee of safety. Previewed code can still make network requests, attempt browser exploits, open popups, or trick you with its content. Run previews only from repositories you trust. Do not enter secrets into a preview.

If a preview calls localStorage, expect a SecurityError — that is the isolation working. The sandbox also prevents top-level navigation, but links inside the preview are intercepted and routed back into RepoDeck where possible.

Browser & project limitations

  • Public GitHub API access needs CORS, which GitHub supports; some corporate proxies or content blockers may still break it.
  • Raw GitHub files are served as text/plain, so scripts and styles must be fetched and inlined — RepoDeck does this for local files. Files fetched at runtime by the preview (fetch('./data.json')) cannot be rewritten and may fail, though the injected base URL helps some relative image/font requests.
  • ES module imports are rewritten into data URLs so they can execute without a server. Code that depends on import.meta.url, relative Web Workers, or dynamically constructed asset URLs may misresolve; bare package imports cannot be bundled.
  • Nested local iframes are replaced with a notice; external iframes are left to the browser. Branch menus list the first 100 branches returned by GitHub.
  • Backend-dependent apps (databases, server-side routing, PHP, Python, Node) are not emulated. RepoDeck never pretends they work.
  • Service workers, Web Workers created from relative URLs, and cross-origin cookies may not work inside the opaque-origin preview.
  • file:// browsers block some APIs; clipboard falls back automatically. Local storage may be unavailable in strict privacy modes — history then lives in memory for the tab.
  • Very large files, binary assets and truncated GitHub trees are handled with warnings rather than downloads of the whole repository.
